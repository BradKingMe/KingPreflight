# KingPreflight — direction candidates

## Product mechanism

A read-only local review of a folder before it leaves its owner: inventory the files, detect selected risk signals, show the limits, and let the person decide what to share.

## Audience scene

Working assumption from the request: a person is about to send, upload, publish, or hand off a folder and wants a quick way to catch obvious accidental inclusions.

## Category rut to avoid

A generic dark SaaS dashboard with a dropzone, three KPI cards, and a table of files. The opposite rut is a literal cockpit with gauges, faux flight controls, and aviation jargon.

## Seven grounded systems

1. **Print-shop proofing table — strongest fit.** Printers already check a proof for errors before committing a run. Use a clean proof sheet, registration/crop marks, one precise warning color, and a readable review ledger. The first screen centers a folder proof with file coverage and a short exception queue; the user can inspect every finding before leaving.
2. **Mailroom dispatch manifest.** A dispatch worker verifies contents and destination before a parcel leaves. Use an ordered manifest, destination label, and unambiguous hold/release states. The first screen pairs the selected folder with a recipient-neutral contents manifest and a few clear holds.
3. **Airport turnaround checklist.** A crew checks safety-critical items before departure. Use short operational language, explicit checked/unchecked states, and a visible stop condition. The first screen is a calm pre-departure checklist; avoid cockpit controls and aviation claims.
4. **Library circulation slip.** A loan card records which item moves and what is due back. Use item records, a compact ledger, and an audit trail. The first screen lists each file with a decision and a reason, with hidden/temporary items clearly separated.
5. **Workshop quality-control bench.** A maker inspects each finished object for defects before packing. Use a work order, sample evidence, and defect categories. The first screen is an inspection sheet focused on concrete findings and false-positive review.
6. **Field-service inspection clipboard.** A technician walks a site and records each finding in sequence. Use durable labels, checklist cadence, and clear evidence notes. The first screen groups scan scope, findings, and a final human decision without decorative machinery.
7. **Browser attachment review.** A sender confirms attachments before pressing Send. Use familiar file rows, simple include/omit controls, and a concise send check. The first screen starts with a folder selection and explains that nothing leaves the browser.

## First-surface success

A first-time user sees how to choose a folder, what the scanner can inspect, what needs human attention, and that the source folder remains untouched. The screen must not imply that “no findings” guarantees safety.
